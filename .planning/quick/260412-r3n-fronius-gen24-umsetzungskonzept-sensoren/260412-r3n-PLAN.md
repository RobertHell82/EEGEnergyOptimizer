**Gliederung des Dokuments:**

## 1. Ziel und Scope
- Fronius Gen24 (+ BYD HVS/HVM Batterie) in den EEG Energy Optimizer integrieren
- Referenz-Setup beschreiben
- Abgrenzung: Konzept, nicht Implementierung

## 2. Lesende Sensoren
- **2.1 Native HA Fronius Integration (Solar API)** — Empfohlener Leseweg
  - Power Flow Sensoren (Update alle 10s): power_photovoltaics, power_battery, power_grid, power_load etc.
  - Storage/Batterie Sensoren (Update jede Minute): state_of_charge, capacity_maximum etc.
  - Entity-Namensschema: `sensor.{device_name}_{key}` — konkrete Beispiele angeben
- **2.2 Mapping auf EEG Optimizer Config Keys**
  - Tabelle: pv_power_sensor, battery_power_sensor, battery_soc_sensor, grid_power_sensor, battery_capacity
  - Vorzeichen-Konventionen dokumentieren (+ Entladung/- Ladung bei Batterie, + Einspeisung/- Bezug bei Grid)
  - Einheiten-Hinweis: Fronius liefert W, EEG Optimizer erwartet ggf. kW — Umrechnung im Inverter-Treiber
- **2.3 Fronius Solar API v1 (direkt)** — Kurz erwaehnen, dass moeglich aber nicht noetig (native Integration reicht)
- **2.4 Modbus TCP Lesen** — Kurz erwaehnen als Alternative, aber nicht empfohlen fuer Lesen

## 3. Wechselrichter-Ansteuerung (Kernthema)
- **3.1 Methode A: HA Native Fronius Integration** — KEINE Steuerung moeglich (Solar API ist read-only)
- **3.2 Methode B: Modbus TCP direkt (pymodbus + SunSpec Model 124)**
  - Voraussetzungen: Modbus TCP aktivieren, int+SF, Allow Control, Port 502
  - Register-Tabelle: StorCtl_Mod (40348), InWRte (40356), OutWRte (40355), MinRsvPct (40350), WChaMax (40345)
  - Steuerungssequenzen: Ladung blockieren, Entladung erzwingen, Normalbetrieb
  - Besonderheit: Prozentwerte statt Absolutwerte (InWRte/OutWRte relativ zu WChaMax)
  - Hinweis: Dynamische Register-Adressen (SunSpec Model Discovery noetig)
- **3.3 Methode B2: fronius_modbus HACS-Integration (empfohlen)**
  - Zwei Varianten: redpomodoro (Original, v0.1.9) vs. callifo (Fork, v0.2.9, aktiver)
  - Empfehlung: callifo Fork
  - Relevante Entities: Storage Control Mode (select), PV Charge Limit (number), Discharge Limit (number), Grid Discharge Power (number), Minimum Reserve (number)
  - Steuerungssequenzen ueber HA-Entities: Block charging, Discharge to Grid, Auto
- **3.4 Methode C: Fronius Solar API v1** — Read-only, keine Steuerung
- **3.5 Methode D: Undokumentierte Web API** — NICHT EMPFOHLEN mit Begruendung (Firmware-Breaking-Changes, CSRF, nicht dokumentiert)

## 4. Vergleichstabelle
- Alle 4 Methoden in einer Tabelle: Sensoren lesen, Ladung blockieren, Entladung erzwingen, HA-nativ, Zuverlaessigkeit, Firmware-Stabilitaet, Auth, Installationsaufwand, Koexistenz
- Uebernahme und Aufbereitung der Tabelle aus der Research

## 5. Empfehlung
- **Primaer:** Native HA Fronius fuer Sensoren + fronius_modbus HACS (callifo) fuer Steuerung
- **Alternativ:** Direkte Modbus TCP Steuerung (pymodbus) als Fallback
- **Nicht empfohlen:** Undokumentierte Web API
- Begruendung mit Bezug auf Praxistauglichkeit, Wartbarkeit, Firmware-Stabilitaet

## 6. Mapping auf InverterBase
- **6.1 Empfohlener Weg: Via fronius_modbus Entities**
  - async_set_charge_limit(power_kw): power_kw=0 -> "Block charging", power_kw>0 -> "PV Charge Limit" + Watt-Wert
  - async_set_discharge(power_kw, target_soc): "Discharge to Grid" + Grid Discharge Power + optional Minimum Reserve
  - async_stop_forcible(): "Auto" auf Storage Control Mode
  - is_available: entries = hass.config_entries.async_entries("fronius_modbus"), state check
- **6.2 Alternativer Weg: Via direkte Modbus TCP**
  - Gleiche Methoden, aber mit Register-Adressen und pymodbus-Calls
  - Prozentwert-Umrechnung: percent = min(power_kw * 1000 / WChaMax * 10000, 10000)
- **6.3 Vergleich mit bestehenden Implementierungen**
  - Tabelle: Huawei vs. SolaX vs. SolarEdge vs. Fronius (HACS) vs. Fronius (direkt)
  - Aspekte: Steuerungsweg, Ladung blockieren, Entladung, Stop, Persistenz, Leistungsangabe, HA-Dependency

## 7. Voraussetzungen fuer den Benutzer
- Fronius Web-Interface Konfiguration (Modbus TCP, int+SF, Allow Control, scheduled charging deaktivieren)
- fronius_modbus HACS-Integration installieren (callifo Fork)
- Firmware-Empfehlung (>= 1.34.6-1, idealerweise >= 1.40.0)
- BYD Battery Management aktiviert

## 8. Offene Fragen (Testgeraet-Verifizierung)
- Exakte Entity-IDs der fronius_modbus Integration am Testgeraet (192.168.100.211)
- Persistenz der Modbus-Werte nach WR-Neustart
- callifo vs. redpomodoro Fork: Stabilitaet bei reiner Modbus-Steuerung
- WChaMax-Zugriff: Abstrahiert fronius_modbus die Prozentwert-Umrechnung?
- Koexistenz native HA Fronius + fronius_modbus in der Praxis

## 9. Besonderheiten und Pitfalls
- Prozentwerte statt Watt (InWRte/OutWRte)
- Keine Auto-Revert (anders als Huawei Timeout) — async_stop_forcible() muss zuverlaessig aufgerufen werden
- Konkurrierende Einstellungen (Web-Interface vs. Modbus: hoeherer Wert gewinnt)
- Dynamische SunSpec Register-Adressen
- Float vs. int+SF Konfiguration
- "Allow Control" muss explizit aktiviert sein
- fronius_modbus ist "Work in Progress" — Entity-Keys konfigurierbar machen, nicht hardcoden
