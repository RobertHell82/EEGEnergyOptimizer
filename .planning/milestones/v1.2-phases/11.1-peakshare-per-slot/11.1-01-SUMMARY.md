## Cache-Lifecycle-Bug-Fix (vorher/nachher)

**Vorher (Phase 11 final):**
```python
# get_discharge_plan, peakshare.py:347-349
if self._discharge_plan_date == today_str:
    return self._discharge_plan.get(slot)
```
Erster Aufruf für Slot A setzte `_discharge_plan_date = today_str`. Zweiter Aufruf für Slot B traf den Cache-Hit (`_discharge_plan_date == today_str`), bekam aber `_discharge_plan.get("b") == None` zurück — Slot B wurde nie berechnet (Tageslock-Bug).

**Nachher (Phase 11.1):**
```python
# get_discharge_plan, peakshare.py
if self._discharge_plan_computed_dates.get(slot) == today_str:
    return self._discharge_plan.get(slot)
```
Pro Slot wird ein eigener Marker geführt. Slot B kann nach Slot A am selben Tag berechnet werden. Test C1 (`test_both_slots_compute_independently_same_day`) prüft das mit echtem (nicht-gemocktem) `PeakShareProvider` und synthetischen api_hours.

`_discharge_plan_date` bleibt erhalten als Backwards-Compat-Touch-Wert (wird in `_discharge_detail_status` und Markdown-Renderer noch gelesen — Plan 11.1-02 baut darauf auf).
