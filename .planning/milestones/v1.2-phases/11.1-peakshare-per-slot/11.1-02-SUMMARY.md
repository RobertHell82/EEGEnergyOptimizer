## Phase-11.1-Gesamt-Bilanz

### Welche Spec-Lücke wurde geschlossen?

Phase 11 SPEC §"In scope" Z. 75 hatte zugesagt:
> „PeakShare-Integration für Dual-Mode (zwei separate Sliding-Window-Suchen, eine pro Slot, mit slot-spezifischem `available_kwh`)"

Plan 11-02 hatte das Cache-Schema (`dict[a/b]`) vorbereitet und Plan 11-04 den Markdown-Renderer für den Slot-Marker erweitert — der eigentliche **PeakShare-Aufruf pro Slot** wurde aber nie nachgeholt. `_evaluate_slot_a/b` entschied bis Phase 11.1 ausschließlich über fixe Zeiten + SOC + Hysterese.

**Phase 11.1 schließt diese Lücke vollständig:**
- Plan 11.1-01: Backend-Verdrahtung (`_evaluate_slot_a/b` rufen `find_discharge_window` mit slot-spezifischen Window-Grenzen auf; Per-Slot-Cache-Tracking; Default-Reserve 5 %).
- Plan 11.1-02: UI-Sichtbarkeit (Markdown-Marker, naechste_aktion-Text, Status-Card-Startzeit zeigen jeweils den aktiven Slot-Plan).

### Welche Locked Decisions wurden umgesetzt?

| # | Locked Decision | Implementierung |
|---|-----------------|-----------------|
| 1 | PeakShare findet Sub-Fenster INNERHALB der Slot-Zeiten | Plan 11.1-01: `find_discharge_window(window_start=a_start, window_end=a_end_cap)` clampt automatisch via Library-internen Mechanismus |
| 2 | Slot A immer bevorzugt; Default-Wechsel 15 → 5 | Plan 11.1-01: `DEFAULT_DISCHARGE_A_RESERVE_PCT = 5` in `const.py`, Migration via `setdefault` (Bestands-Schutz). CHANGELOG dokumentiert (Plan 11.1-02) |
| 3 | Fallback auf Fixzeit pro Slot (kein Slot-Ausfall) | Plan 11.1-01: `if peakshare_plan is None: # Fixzeit-Fallback`-Pfad in `_evaluate_slot_b`; Slot A nutzt impliziten Fallback (kein PeakShare-Aufruf bei `available_kwh ≤ 0`) |
