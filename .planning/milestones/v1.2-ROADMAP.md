# Roadmap: Optimizer-Erweiterungen

## Overview

Dieses Milestone erweitert die Entladelogik des EEG Energy Optimizers um differenzierte Einspeise-Strategien, die Abend- und Morgen-EEG-Bedarf unabhängig adressieren. Im Fokus steht ein Dual-Window-Modell, das den heute aktiven Single-Window-Ansatz ablöst (oder bei Bedarf als Fallback erhält).

**Hintergrund:** Mit `discharge_start_time = 01:00` gewinnen wir Genauigkeit (Nachtverbrauch ist um 01:00 bekannt), verlieren aber den EEG-Mehrwert der Abendstunden (20:00–01:00) und der Morgenstunden vor Sonnenaufgang. Ein Dual-Window-Modell mit getrennten Energie-Budgets adressiert beide Lücken.

- [x] **Phase 11.1: PeakShare-Steuerung der Slot-A/B-Fenster** (INSERTED) — Slot A und Slot B nutzen die PeakShare-Sliding-Window-Suche zur Optimierung des Entlade-Sub-Fensters innerhalb der konfigurierten Slot-Zeiten; Fixzeit-Fallback pro Slot wenn Daten fehlen. Schließt Spec-Lücke aus Phase 11 (SPEC §"In scope" Z. 75 — PeakShare-Integration für Dual-Mode wurde dort versprochen, aber nie umgesetzt). **Verified** 2026-05-04, manual UAT pending.
- [x] **Phase 12: SolaX Charge-Block ohne Battery-Idle** (Completed 2026-05-15) — `async_set_charge_limit(0)` setzt bei SolaX `battery_charge_max_current=0` statt Mode 1 "Enabled Battery Control + 0 W". Damit blockiert Morgen-Einspeisung nur noch das Laden — Self-Use-Discharge bis `selfuse_discharge_min_soc` läuft weiter wie bei Huawei/Fronius. Verhindert das beobachtete SOC-Einfrieren bei ~19 % während Morgen-Einspeisung. Original-Wert persistiert via Storage.

### Phase 11.1: PeakShare-Steuerung der Slot-A/B-Fenster (INSERTED)

**Inserted:** 2026-05-04, nach Phase 11 — schließt die in Phase 11 SPEC §"In scope" Z. 75 versprochene "PeakShare-Integration für Dual-Mode (zwei separate Sliding-Window-Suchen, eine pro Slot)", die in Plan 11-02 nur SCHEMA-seitig vorbereitet wurde (Cache als `dict[a/b]`, slot-Parameter in `get_discharge_plan`) und auf 11-04 vertagt, dort aber nie umgesetzt.

**Kurz-Ziel:** Wenn PeakShare aktiv ist und Community-Daten den Slot-Zeitraum abdecken, ermittelt der Optimizer pro Slot ein optimales **Sub-Fenster** innerhalb der konfigurierten Slot-Grenzen (Beispiel: Slot A 20:00–03:00 → PeakShare findet 22:00–00:00). Slot-A wird bevorzugt; `discharge_a_reserve_pct` Default sinkt von 15 % auf 5 %. Fehlt PeakShare oder die Datenabdeckung, fällt der betroffene Slot auf Fixzeit zurück (heutiges Slot-A/B-Verhalten).

**Locked design answers (vor Spec-Refinement):**
1. PeakShare optimiert **innerhalb** der Slot-Zeiten — keine Überschreibung der Slot-Grenzen.
2. Slot A bevorzugt; `discharge_a_reserve_pct` Default-Wechsel 15 % → **5 %**.
3. Fallback auf Fixzeit pro Slot wenn PeakShare-Daten fehlen.

### Phase 12: SolaX Charge-Block ohne Battery-Idle

**Inserted:** 2026-05-15 — Inverter-Driver-Bug entdeckt durch User-Observation (SOC bei ~19 % eingefroren in Nacht 14./15. Mai).

**Kurz-Ziel:** Bei Morgen-Einspeisung blockiert der SolaX-Driver heute via `remotecontrol_power_control = "Enabled Battery Control"` + `active_power = 0` — das setzt die Batterie komplett auf Idle (weder Laden noch Entladen). Resultat: Hausverbrauch wird aus dem Netz bezogen, statt aus der Batterie wie bei Huawei/Fronius. Phase 12 ersetzt diesen Mechanismus durch `battery_charge_max_current = 0` — Self-Use-Mode läuft im Hintergrund weiter, `selfuse_discharge_min_soc=10%` bleibt aktiv als Untergrenze.

**Diagnose-Belege:**
- Nacht 14./15. Mai: SOC fiel im Self-Use-Mode von 45 % auf 19 % (durch Hausverbrauch), Morgen-Einspeisung startete um 05:24 lokal und fror SOC bei 19 % ein → SOC konstant 19 % bis 11:00.
- Nacht 13./14. Mai: Keine Morgen-Einspeisung aktiviert → SOC fiel sauber bis 10 % (= `selfuse_discharge_min_soc`).
- SolaX-Konfiguration unverändert: `selfuse_discharge_min_soc=10`, `backup_discharge_min_soc=20`, `charger_use_mode="Self Use Mode"`.

**Locked design answers (aus Diagnose-Gespräch 2026-05-15):**
1. Lösungsweg: `battery_charge_max_current = 0` (Variante 1 — analog Huawei `batterien_maximale_ladeleistung`, Fronius `StorCtl_Mod Bit 0 + InWRte=0`).
2. Persistierung: Original-Wert via `homeassistant.helpers.storage.Store` — überlebt HA-Reboots. Reboot-mitten-im-Block-Schutz: Cache nur befüllen wenn aktueller State > 0.
3. Migration v12 → v13: neuer Config-Key `solax_battery_charge_max_current` mit Default `number.solax_inverter_battery_charge_max_current`.
4. `async_set_discharge` bleibt unverändert (nutzt weiter Mode 1 mit negativer Power — funktioniert korrekt).
5. `async_stop_forcible` setzt Mode 1 explizit auf Disabled UND restoriert `battery_charge_max_current` aus Store.
